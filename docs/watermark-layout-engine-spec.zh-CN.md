# 摄影水印排版引擎：开发规范与验收标准

版本：草案 v1，2026-11-12。状态：待实现、待真实素材验收。

本文规定目标行为，不代表现有功能已实现或通过验收。适用于文博摄影的单组图文水印；不包含满屏防盗平铺水印、海报标题或图片扩展生成。

## 1. 产品目标与优先级

**照片是主角，水印不得喧宾夺主。这是最高优先级。**

用户确认的约束：

1. 每张成片只出现一组水印，文案只写一遍。
2. 横排或竖排由照片空间决定，不固定使用某个方向。
3. 不加分割线；默认也不加底板、边框、描边、阴影。
4. 使用用户提供的图案，字体和颜色可以调整，以协调为准；不绑定细金陵。
5. 水印需要可读，但不能用放大、增亮的方式把它变成标题。
6. 保持原图、文案和图案准确，不用生成式模型重绘成片。

决策顺序：硬约束合规 → 不干扰主体 → 与背景协调 → 达到必要可读性 → 内部排版精致。不得以加权总分抵消硬约束失败。

## 2. 输入与数据契约

建议接口；实现时可适配现有类型，不要求直接复制。

```ts
interface WatermarkRequest {
  sourceId: string;
  sourceWidth: number;       // 应用 EXIF 方向后的像素宽
  sourceHeight: number;
  content: {
    title: string;          // 必填，唯一内容源
    description: string;    // 可空
    credit: string;         // 可空
  };
  symbolId?: string;
  direction: 'auto' | 'horizontal' | 'vertical';
  protectedRegions: Region[];
  allowedRegions?: Region[];
  analysisStatus: 'manual' | 'estimated' | 'unavailable';
  overrides?: {
    fontId?: string;
    color?: string;
    opacity?: number;
    position?: { x: number; y: number };
    scale?: number;
  };
}
interface Region {
  // 相对完整、定向后原图的归一化坐标，范围 [0, 1]
  x: number; y: number; width: number; height: number;
}
```

示例文案只在此定义一次，测试引用字段，不在结果中追加原文说明：

```json
{
  "title": "赵孟頫行书秋声赋卷",
  "description": "元 · 辽宁省博物馆藏",
  "credit": "笑谈间气吐霓虹摄"
}
```

该文案叠加在木雕照片上时只作为用户指定的排版测试，不是对木雕名称、年代、藏馆的认定。生产模式不得推断或替换作品信息。

### 文案唯一性

- 各字段对应稳定的内容 ID，布局节点引用内容 ID 和字符范围。
- 允许换行、分列和调整视觉间距；不允许改写、复制字段、漏字或转换简繁。
- 每个非空字段的每个 Unicode 字符必须按原顺序消费一次。按码点记录范围，避免 UTF-16 下标拆断字符。
- 允许渲染用户输入的相同词语；不能通过全文去重误删合法重复。
- 字段间间隔使用布局留白；默认不自动插入斜杠等标点。用户输入的标点保留。
- 预览与导出只合成一组。对比板、放大细节不属于默认交付物。

## 3. 硬约束与失败行为

| ID | 要求 | 失败处理 |
| --- | --- | --- |
| H01 | 一组水印，内容准确且仅消费一次 | 阻止导出并报告字段/字符范围 |
| H02 | 不进入主体、原作文字、印章等保护区 | 淘汰候选；无可用候选则要求手动定位 |
| H03 | 不越界、不裁切文字或图案 | 淘汰候选 |
| H04 | 不改变原图比例、构图与背景内容 | 阻止导出 |
| H05 | 图案比例、内纹、孔洞和透明边缘保真 | 阻止使用失真的素材 |
| H06 | 实际字体加载成功，所有字符有字形 | 等待或明确提示更换字体，不静默替换 |
| H07 | 默认无分割线、底板等附加装饰 | 配置校验失败 |
| H08 | 预览和导出共用同一份布局 | 不允许导出时重新自动排版 |

保护区应加入至少 `0.5 × 主字号` 的避让缓冲。缺少主体检测结果不等于不存在主体；自动定位应返回低置信度，不能宣称已避让。

自动无解时返回 `needs-manual-placement`，保留原图与输入。不得靠覆盖主体、裁图、生成留白或把文字无限缩小强行成功。

## 4. 尺度与排版规则

以下为首轮实验参数，不是已验证的通用审美阈值。以定向后原图短边 `S` 为基准；测量对象采用实际字形墨迹边界，不只用字体 em 框。

| 参数 | 初始范围/默认值 |
| --- | --- |
| 主字号 | `0.010S–0.015S`，初值 `0.012S` |
| 辅助字号 | 主字号的 `0.75–0.85`，初值 `0.8` |
| 安全边距 | `0.04S–0.07S`，初值 `0.05S` |
| 图文间距 | 主字号的 `0.4–0.7` |
| 横排行高 | 对应字号的 `1.25–1.45` |
| 竖排列距 | 对应字号的 `1.3–1.6` |
| 常规字距 | `0–0.08em`，禁止为凑宽大幅拉开 |
| 字重 | 正常或中等；避免极细字和粗黑大字 |
| 横排图案高度 | 不超过文字组高度，优先取 `0.75–0.9` 倍 |
| 竖排图案高度 | 不超过主字号的 `1.5` 倍 |

面积、总宽和总高必须同时记录；细长水印不能仅因面积小就判定合格。建议初期将包围盒面积超过原图 `1.5%` 的候选标为人工复核，不把这个值当作审美通过证明。候选缩放仍需受可读性检查约束。

### 模板限制

首版仅实现三个模板，防止自由组合失控：

- `horizontal-2`：左图案，右侧两行；第一行作品信息，第二行辅助信息。辅助信息过长时切换三行，不能强行压缩字形。
- `horizontal-3`：左图案，右侧作品、藏馆、署名三行，文字左对齐。长标题可在语义边界换行，但不要把作者做成大标题。
- `vertical-2`：图案在上，主文与辅助文双列，主列在右，从上往下排；标点使用正确竖排字形，不把整段横排文字旋转九十度。

标题与辅助信息只设两个字号层级。默认同字体、同颜色。禁止重叠、水平压扁字体、把图案放大为独立徽章。

### 方向与位置

- 宽浅空白优先横排，窄长空白允许竖排；都能容纳时比较实际渲染结果。
- 优先靠近画面边缘的安静区域，避免把水印孤立在画面中央形成第二主体。
- 边缘不是无条件安全区，书画题跋、印章同样需要保护。
- 不将“书法必竖排、雕塑必横排”写成固定规则。
- 手动指定方向和位置优先；若违反保护区仍需显示冲突，不能声称自动验收通过。

## 5. 字体、图案与配色

字体从少量已核验的宋体、楷体、人文黑体中生成候选，不根据作者姓名擅自模拟作者书风。覆盖测试至少包含常见字、生僻字、繁体字、数字和标点。加载字体后再测量，测量和渲染使用同一个字体文件与字重。

图案优先使用透明源文件。白底转透明属于显式素材准备步骤，应核对内纹空洞和抗锯齿边缘；不能用不透明白块覆盖背景。保持宽高比，颜色仅作用于原图案有效 alpha。默认禁止使用包含额外署名的图案，避免署名重复。

配色基于实际落点的局部背景，不使用整图平均色。先选择低饱和深色或浅色，再联合评估颜色、透明度与位置：

1. 浅底优先灰褐、柔和暗赭；深底优先灰米、柔和浅灰。
2. 默认图案与文字同色，不使用高亮纯白、亮金或鲜红作为通用默认值。
3. 不固定低透明度；透明度过低使文字破碎时，换位置或适度调整颜色。
4. 对比度必须按最终 alpha 与背景合成后计算；不能只检查未合成的前景颜色。
5. 不把 UI 正文对比度标准直接当作摄影水印审美标准。现有对比度覆盖率可作诊断，不能代替人工辨读和视觉协调验收。
6. 禁止对预着色素材和最终水印重复乘全局透明度。

## 6. 引擎与 Agent 边界

确定性程序负责：内容范围、字体加载与字形、文字测量、换行、布局、配色计算、坐标变换、合成和导出。

视觉 Agent 可建议：保护区、候选区、方向、字体候选和协调评分。Agent 仅返回结构化参数，不生成最终照片，不改文案，不拥有绕过硬约束的权限。没有 Agent 时必须能使用人工区域完成排版。

流程：校验输入 → 准备素材与字体 → 分析/读取区域 → 生成至多 6 个候选 → 真实渲染 → 硬约束淘汰 → 视觉排序 → 锁定布局 → 预览/导出。

排序采用逐级比较，不用一个总分掩盖问题：先排除干扰主体者，再比较协调程度；可读性达到要求后不继续追求更醒目。视觉判断保留理由和置信度，不包装成客观测量。

建议输出记录：

```ts
interface LayoutResult {
  status: 'ready' | 'needs-manual-placement' | 'invalid-input';
  templateId?: string;
  // layout 使用定向后原图像素坐标；保存每个内容片段的范围和墨迹边界
  layout?: unknown;
  metrics: {
    bboxAreaRatio?: number;
    widthRatio?: number;
    heightRatio?: number;
    protectedOverlapPixels?: number;
  };
  warnings: string[];
  // 保存输入摘要、字体/图案校验值、规则版本与人工覆盖，便于复现
  manifest: Record<string, unknown>;
}
```

缓存键应包含源图、文案、字体文件、图案、区域、参数和规则版本。异步分析采用请求版本号，只允许最新请求更新预览；导出锁定当前已完成布局，避免旧请求覆盖新设置。

## 7. 预览与导出保真

- 原图坐标统一计算，预览只对同一布局做等比变换；UI 缩放不改变导出字号。
- 默认输出定向后原尺寸，不拉伸、不裁切；颜色管理与输出色彩配置必须记录。
- “水印外像素不变”在同一个已解码工作色彩空间的合成缓冲上验证。PNG 无损输出可做像素回读；JPEG 有损编码及色彩转换不能要求水印外文件解码像素逐点相同。
- 像素差异检查范围为水印实际 alpha 支持区域及栅格化边缘，不只用文字逻辑边界。
- 大图分块导出使用相同全局布局和颜色，检查块边接缝，不分块重新选位置。
- 源文件只读，导出到新文件。检查透明度仅应用一次，原图自带 alpha 按既定合成规则保留。

## 8. 验证用例与通过条件

| ID | 场景 | 通过条件 |
| --- | --- | --- |
| T01 | 正常文案、三个模板 | 每个字段字符消费恰好一次，仅一组水印 |
| T02 | 文案包含合法重复词、生僻字、emoji | 不误去重、不拆字符；缺字时明确失败 |
| T03 | 空辅助字段、超长标题 | 无空白占位；合理换行或返回手动处理 |
| T04 | 浅纸底书法、题跋和多印章 | 不进入保护区；无可用位置不强行覆盖 |
| T05 | 暗红背景木雕、大块留白 | 横竖均可比较；不自动生成大标题或亮金色 |
| T06 | 满幅纹理、复杂明暗、主体贴边 | 低置信度/无解可解释，不自动加底板描边 |
| T07 | 横图、竖图、长卷、EXIF 旋转 | 坐标正确、原比例保留、无越界 |
| T08 | 100%/50%/0% alpha、透明原图 | 全局 alpha 只应用一次；0% 时无水印差异 |
| T09 | 预览缩放、浏览器 DPR、原尺寸导出 | 归一化布局一致；栅格边界误差至多 1 个目标像素 |
| T10 | PNG 与 JPEG 导出 | 尺寸/方向正确；按第 7 节分别验证保真 |
| T11 | 慢字体加载、连续改色改字切图 | 不闪回旧布局；导出与当前确认预览对应 |
| T12 | 大图分块与正常路径 | 全局位置一致，无块缝/重复水印 |
| T13 | 手动覆盖后重新分析、批量图片 | 手动设置不被静默覆盖；每图独立校验位置 |
| T14 | 图案去底、着色、缩放 | 无白底、内纹孔洞保留、无拉伸或双重 alpha |

### 人工视觉验收（必须执行）

每张真实样张分别检查整图适屏、实际发布尺寸和局部原尺寸。默认交付只显示一张完整成片，不附重复文案或放大水印；开发诊断视图可独立打开。

- 整图：先注意到照片主体；水印没有形成第二个视觉中心。
- 发布尺寸：主动寻找时能辨认，字重不过细，颜色不刺眼。
- 局部：文案准确、无缺字、边缘干净，图案比例和内纹正确。
- 一旦用户认为喧宾夺主，视觉验收失败；自动指标通过不能覆盖此结论。

记录检查者、显示尺寸、原图/结果路径、选择理由、失败点。产品负责人或用户确认视觉通过，不能由生成方案的 Agent 自评后直接宣布完成。

## 9. 素材与回归记录

本次用户提供的书法 JPEG（3527×5644）、木雕 PNG（9504×12672）、玉印排版示意和纯图案源文件作为人工验收素材。实现时应从真实文件重新读取尺寸与校验值，不依赖聊天缩略图或前几次生成图。

原文件位于用户 Downloads 或临时目录，不能作为仓库永久测试依赖。首次建立本地测试清单，记录来源、尺寸、SHA-256 和用途；不默认将用户照片提交到 Git。临时目录素材可能失效，缺失时明确标记，不能用生成图替代真实原图验收。

建议在本地忽略目录保存 `manifest.json`、完整成片、布局 JSON、自动检查报告及人工检查记录。每次报告区分：静态检查通过、自动回归通过、真实图片导出通过、人工视觉通过。未做的项目写“未验证”。

## 10. 接入现有项目与实施顺序

现有入口供开发定位，须先复核其实际行为：

- `src/utils/text-watermark-layout.ts`：布局几何。
- `src/utils/text-watermark.ts`：文字水印相关实现。
- `src/utils/watermark-processing.ts`：处理链路。
- `src/pages/watermark/smart-watermark.ts`：智能水印相关实现。
- `scripts/test-watermark-layout.mjs`、`scripts/test-watermark-typography.mjs`：已有相关检查。
- `docs/watermark-fonts-and-menu-checks.md`：既有实现与验证记录。

现有布局函数对多项内容主要处理前两项，接入三字段前必须核对，不能直接传入第三项后假设已渲染。新规范的字体策略也不同于既有固定字体回退记录，需要显式迁移，不能把文档更新当作代码已生效。

实施阶段：

1. **M1：确定性排版。** 人工指定区域，完成唯一内容源、三个模板、字体测量、统一布局与无损合成检查；通过 T01–T03、T07–T10、T14。
2. **M2：位置与配色候选。** 在人工区域内搜索，加入硬约束淘汰与无解返回；通过 T04–T06 和真实素材视觉验收。
3. **M3：自动分析/Agent。** 输出区域与建议，保留人工覆盖、版本控制和可复现记录；通过 T11、T13，不降低前两阶段门槛。
4. **M4：大图与批量。** 验证真实原分辨率、分块路径与批量状态隔离，通过 T12，并重新核对最终交付物。

完成定义：相关自动用例通过，真实原图导出经过检查，人工确认不喧宾夺主，未验证项和限制已写入报告。仅有概念效果图或构建成功不算完成。
